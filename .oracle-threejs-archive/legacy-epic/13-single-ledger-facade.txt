# Findings

**1. `run_executor` signature & run-creation decision** — `ExecutorCapabilityRunner.run` (capability_runner.py:106) → `prepare_project` → `_prepare_project_request` (executor/runner.py:920): **`request.project` falsy → `(None, request)`, no run.json** (runner.py:924-925). Project set → `prepare_project_run` (project/run.py:145): **fresh run.json at a new run_id** (run.py:252-280), **unless** `ASTRID_TASK_PROJECT/RUN_ID/STEP_ID` are set, which routes to the parent's `step_dir_for(...)` with `run_id=parent_run_id`, **no run.json written** (run.py:190-242); `finalize_project_run` also skips writes for attached children (run.py:421-425). `maybe_gate` (runner.py:209) gates only inside task runs; `invocation="attached-child"` skips it (runner.py:216-217). Orchestrator's `_prepare_project_request` (orchestrator/runner.py:600-631) sets `run_root=context.run_root` on the request; iteration_video reads it via `_attached_render_binding` (iteration_video/run.py:190-201).

**2. CLI path** — `_cmd_run` (cli_handlers.py:375): `_gateway_resolved_project` (capability_common.py:53) reads `ASTRID_GATEWAY_RESOLVED_PROJECT`, set by `_dispatch_with_resolved_project` from the **attached session** for `executors run` (gateway/project.py:152-176). **No "no project" mode**: session → auto-resolved project → nested run.json; no session/`--project` → `ExecutorRunnerError` guidance (runner.py:1048-1058).

**3. Hype render** — render Step uses `invoke=invoke_hype_render` (steps.py:419-425) → `invoke_attached_render` (steps.py:192; attached.py:44-159): in-process `run_executor`, `invocation="attached-child"`, scoped task env, **no render run.json** — only the orchestrator run exists. `build_hype_render_cmd` (steps.py:143) is the legacy subprocess argv, unused for execution. iteration_video: same attached pattern (run.py:158-176).

**4. Existing pattern** — `invoke_attached_render` (attached.py:44-159) = "child capability without nested run": attached.py:130-144.

## Verified facts
Run creation = `request.project` AND no task env → new run.json; task env → parent-attached step dir, never a new run.json.

## Unknowns
Whether `Step.invoke` fallback ever subprocess-spawns `build_hype_render_cmd`; SDK `run_executor` (sdk/invocation.py:24) behavior.

## Risks
Session auto-binding creates nested runs (gateway/project.py:152); explicit `--project` on leaf subprocesses; `prepare_project_run` refuses non-empty `ledger_out` (run.py:258-259); `--project`+`--out` rejected unless auto-resolved (runner.py:927-928).

## Suggested approach
Invoke the facade in-process exactly as attached.py:130-144: `ExecutorRunRequest(executor_id="rendering.render", project=<parent>, project_was_auto_resolved=True, invocation="attached-child", out=<existing run_root>, inputs=...)` under scoped `ASTRID_TASK_*` env — reuses the orchestrator's run, zero new run.json.
