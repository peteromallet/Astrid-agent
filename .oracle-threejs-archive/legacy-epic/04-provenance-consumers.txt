## Provenance sidecar: consumers & lifecycle

**1. Writers.** `run.py` (facade) only forwards; the sidecar is built in `core/rendering/provenance.py:442-471` (`assemble_provenance_v2`): `schema_version:2`, `engine`, `output`, `timeline`, `assets_registry`, `request_digest`, `requested_policy`, `resolved_policy`, `routing` (auto-route lineage), `planner`, v1-projection `segments`, additive `segments_v2`, `artifact_profiles` (hashed per-segment lineage: profile/sha256/attachments), `audio_ownership`, `normalization`, `finalizer`, `attachments`, `backend_fragments`, plus `v1_compatibility` fields (`service.py:2158-2171`: project_dir, composition_id, active_pack_order, active_theme, registry_hash/state, resolved_effect_ids/effects, source_pack_ids, element_roots, staged_asset_ids/root; `ffmpeg_specialization`, `audio_reactive_colour`; multi-segment `segment_provenance`). Called at `service.py:575-587`; `sha256`+`output` injected at publish (`publication.py:360-363`).

**2. Cleanup.** `run.py:138-161` only discovers sibling `runs/*/hype.mp4` candidates (timeline arg unused). Matching/deletion is `publication.py:240-307`: non-blocking per-candidate lock, `read_committed_provenance` + `provenance["timeline"]==timeline` (`:293-294`), sidecar unlinked before video (`:296-305`). Not set-atomic: sidecar-first leaves recoverable orphans; locked candidates skipped.

**3. Consumers.** Only runtime field readers are `output`/`sha256` (commit validation, `publication.py:193-209`) and `timeline` (cleanup). `attached.py:151-157` requires existence, records pair. `cli.py:742,1066-1068` (replay copies), hype (`steps.py:421`), iteration_video (`run.py:30`), cut (`run.py:408`, `resume.py:197`), sdk docstring — pass-through. Tests read `segments_v2`/`artifact_profiles` (`tests/core/rendering/test_service.py:653,716,1793`). `editorial/refine/run.py:631` and `prepare/run.py:438` read thread provenance, **not** the sidecar.

**4. No-sidecar.** None on success — every `service.render` publishes a pair; only pre-publish failures leave none (test_service.py:862,965). `legacy_engine.py` is dead (no importers) but ffmpeg/audio-reactive paths emit `legacy_v1` fragments.

**Verified facts:** field list above; 2 field-level consumers + 7 pass-through.

**Unknowns:** replay-bundle sidecar integrity expectations; whether anyone parses `routing`/`resolved_policy` externally.

**Risks:** `read_committed_provenance` hard-requires `sha256`/`output`; `segments` flat projection relied on by v1-era tooling; dropping `v1_compatibility` breaks schema validation (`provenance.py:374-394`).

**Approach:** keep `output`/`sha256`/`timeline` stable, preserve `segments`+v1 keys as projections, add fields additively — the current v2 already does this; migrate by bumping `schema_version` with a reader that tolerates both.
