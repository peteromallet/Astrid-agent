## Verified facts
- Every production render invocation goes through `invoke_attached_render` (in-process) or `python -m astrid executors run rendering.render` (subprocess/plan argv). No production module imports or `-m`-spawns the concrete module; `test_production_callers.py` enforces this.
- The alleged `from ..render.run` (cut/run.py:367, cut/resume.py:163) **does not exist** — it was a real historical bug, already migrated; `test_cut_render_migration.py:118-127` guards regression. Same for `executor_argv("render.py")` in hype/steps.py and `_step_argv("render.py")` in human_notes/run.py — both now canonical.
- iteration_video does **not** rename hype.mp4→iteration.mp4: it passes `output_name=iteration.mp4` into the facade; the service derives the sidecar as `{output}.provenance.json` (service.py:357, executor.yaml:187), so provenance follows the name — no stale output field. Note `_previous_render_outputs_for_timeline` (render/run.py:150) only cleans siblings when the name is `hype.mp4`.
- `cut --renderer`: declared **not** in executor.yaml but in `cut/run.py:123-129` — `add_choice_arg(parser, "--renderer", values=("remotion",), default="remotion", help="Deprecated render selector; forwarded to rendering.render as its engine selector.")`; accepts only `"remotion"`; forwarded `engine=args.renderer` (cut/run.py:378) → attached `_one_selector` → `inputs["engine"]` → facade `--engine`. iteration's `--renderer` (run.py:404-407, 425-429) is an unconstrained string, same forwarding.
- `executor_argv`/`_step_argv` (argv.py:10-45): qualified ids via `registry.get`, bare names via unique `metadata.pipeline_step`, returns `metadata.runtime_module` → `[python, "-m", module]`. **Deliberately uncached** — `load_default_registry` rebuilds each call and reads `OverrideStore` fresh; the "global caching claim" is false for resolution (runner.py's `lru_cache`s cache only module imports, not resolution).

## Unknowns
- Whether the provenance sidecar's internal schema records a hardcoded `output`/`video` filename that could disagree with a non-default `output_name` (assembled via `assemble_provenance_v2`, not inspected field-by-field).
- Whether the Arnold `shapes.py` references are executed elsewhere in-process (data-only here).

## Risks for migration
- Stringly-typed id spread (planned_commands tuples, arnold shapes, html_canvas_effect metadata, docs) must all move together if `rendering.render` is renamed — only attached.py/registry.py use the constant.
- Test patches of `render_facade.render` / `_default_service` pin facade internals, coupling refactors to tests.
- `tools/render_and_check.py` bypasses the attached seam and hardcodes `hype.mp4` (with a `--bypass` escape hatch).
- `_previous_render_outputs_for_timeline` behavior diverges for non-`hype.mp4` outputs.

## Suggested approach
Keep `invoke_attached_render` as the sole runtime seam; centralize the executor id in one constant (`_FACADE_EXECUTOR_ID`) and replace all string references; declare `--renderer` choices in the executor manifest; steer tests toward monkeypatching `invoke_attached_render`; extend the production-callers grep to cover `rendering.render` spawn strings (already partially done at test_iteration_video.py:179).
