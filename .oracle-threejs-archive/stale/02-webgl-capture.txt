## Verified findings (ranked by relevance)

**1. Determinism is already engineered into `@remotion/three@4.0.455`** — primary source, `ThreeCanvas.tsx` (raw.githubusercontent remotion v4.0.455): `delayRender('Waiting for <ThreeCanvas/> to be created')` resolved in R3F `onCreated` (fires after GL context); per-frame `delayRender` before `state.advance(performance.now())` keyed to `useCurrentFrame()`, `continueRender` only after R3F draws (`frameloop='never'` when `isRendering`). Remotion's screenshot therefore always follows a completed WebGL frame. If context creation fails, `onCreated` never fires → 30 s delayRender timeout ("stuck render"), not a black frame.

**2. Chrome**: `@remotion/renderer` downloads **Chrome Headless Shell**, never system Chrome — `node_modules/.remotion/chrome-headless-shell/[platform]/` (remotion.dev/docs/miscellaneous/chrome-headless-shell; repo docs/reference/threejs-renderer.md:63). Always headless; not in `~/Library/Caches`.

**3. GL flags**: Remotion 4.0 default `gl: null` (Chrome decides; `angle` default only in 5.0). Options: `angle|egl|swiftshader|swangle|vulkan|angle-egl`. Your config already passes the documented @remotion/three requirement: `remotion/remotion.config.ts:13` `Config.setChromiumOpenGlRenderer('angle')` → `--use-gl=angle` (ANGLE→Metal on macOS arm64; hardware WebGL, fine).

**4. Breakage**: Chrome 129+ removed automatic SwiftShader WebGL fallback (chromestatus 5166674414927872) — needs `--enable-unsafe-swiftshader` on GPU-less hosts. SwANGLE (`--use-gl=angle --use-angle=swiftshader`) is the explicit, supported path (chromium issue 40051729).

**5. CI (ubuntu-latest, `.github/workflows/ci.yml:17`)**: backend runs `npx remotion render … --allow-html-in-canvas --enforce-audio-track` (remotion/run.py:692–704) — **no `--gl`**; `chromiumOptions` (4.0.455) has no generic args field; `rendering.threejs` rejects backend_config (run.py:438). Flags can only live in `remotion.config.ts` or a `browserExecutable` wrapper.

**6. Not run here** (no shell tool, no node_modules). Try: `cd remotion && npm ci && npx remotion render ThreeTimelineComposition --props p.json --output out.mp4 --gl=swangle --frames=0-0`; add `--enable-unsafe-swiftshader` via wrapper only if needed.
