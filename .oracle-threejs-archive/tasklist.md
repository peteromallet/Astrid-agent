# Tasklist: three.js renderer

This tasklist is frozen. The architecture boundary is: Three renders only background/plain-text timelines inside the existing `remotion/` project through `@remotion/three` and Remotion Chromium; the thin Python backend owns Three identity and provenance while reusing Remotion’s execution helper and single global lock; the opt-in hybrid planner performs temporal Three/Remotion routing and pins `rendering.ffmpeg-finalizer`. Do not add another browser, capture loop, encoder, lock, Node project, scene DSL, or spatial compositor.

No production file under `astrid/core/` may change. Every batch must prove this against the preceding accepted checkpoint SHA. Plan changes require oracle approval; executors must not silently broaden scope. Batches are ordered to prove the exact dependency/WebGL stack before composition or adapter work, then add the renderer, planner, integration coverage, and delivery verification. Do not begin a batch until the oracle passes the preceding checkpoint.
