## Risks & Conflicts

1. **Sisypy adapter void is the single biggest risk.** The plan (tasklist.md line 61) already notes "Sisypy non-recursive evidence capture." Without an Astrid adapter that recursively preserves the `agent-view/` bundle, the stdout-discovery gate (T35) and image-only gate (T34) cannot mechanically capture what the agent produced. This is a **blocker for M2**.

2. **No VLM credentials in CI mean live gates can never run on push.** The plan wants "every VLM failure converted into a durable fixture" (plan:912), but without CI credentials, failures can only be captured on a developer machine. The nightly gate must be designed as a separate workflow with repository secrets — this is a **security boundary that must not be blurred** with the credential-free CI.

3. **Single monolithic CI job** (ci.yml:15 — `timeout-minutes: 55`) will not accommodate live VLM evaluation (which could take 10–30 minutes per fixture × 3 sessions). The live gate must be a separate job or workflow to avoid pushing the hermetic CI past its timeout.

4. **The `xxhash` dependency is unused** in the current codebase for hashing. If the plan intends to use it for fast file hashing, that's fine — but if it expects it to already be wired in, that's a gap. The existing `compute_sha256` and `hash_file` use `hashlib.sha256()` directly.

5. **The plan's tasklist (T36) bundles CI, docs, and release evidence into one task.** These are three separate concerns: credential-free CI (already exists but needs a marker lane), nightly VLM gate (doesn't exist), and evidence retention (currently only coverage.xml). They should be three distinct implementation units.

## Elegant Simplifications

1. **Recursive evidence capture is a one-liner in the adapter.** Instead of redesigning Sisypy's `capture_evidence()`, implement `AstridProjectAdapter.capture()` to do `shutil.copytree(agent_view_dir, evidence_dir / "agent-view")` after verifying the manifest exists. The plan requires "recursive capture of the whole bundle" (A9) — the adapter's `capture()` hook already receives the `evidence_dir` and can recursively copy. No Sisypy changes needed.

2. **Reuse `integrity.py` + `cas.py` for all snapshot hashing.** The plan needs root snapshot hashes, media hashes, and verified-original checks. `compute_sha256()` (integrity.py:12) does streaming file hashing; `canonical_json_digest()` (cas.py:93) does deterministic JSON hashing. Compose these — don't build new hashing. The `verify()` pattern (integrity.py:30) already compares hash+size and returns `"ok"|"missing"|"mismatch"` — directly reusable for verified-original checks.

3. **Three-session independence = three Sisypy runs with different `--tag` values and fresh `ActorRun` records.** Sisypy already supports this: each `run_scenario()` call creates a distinct `ActorRun` with its own `evidence_dir`. The "fresh session" requirement is satisfied by running the same scenario three times with different tags and asserting that each independently meets the ≥95% threshold. No new harness code needed — just a wrapper script.

4. **Split hermetic vs. live with existing marker infrastructure.** Add `live` + `vlm` markers to `pyproject.toml` `markers` list. The existing `-m "not integration and not opt_in"` pattern scales trivially to `-m "not integration and not opt_in and not live and not vlm"`. The nightly gate workflow overrides this filter. No new lane machinery needed.

5. **The failure→fixture rule can use `shutil.copytree` of the evidence directory.** When a VLM run scores below 95%, the Sisypy evidence pack already contains everything: the exact image bundle (if captured recursively), the questions, the model identity, the answers, and the ground truth. "Convert to fixture" = copy the evidence dir to `tests/fixtures/timeline_visualize/<failure-id>/` plus a README.md with the expected score. This is a post-run script, not a harness change.
