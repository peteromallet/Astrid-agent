# m1 — Event core and repositories (sprint-plan Sprint 1)

Normative references: `docs/unified-data-model-plan-v10-20260813.md` (§2 schema/layering + §5.1 invariants), `docs/astrid-first-sprint-plan-20260813.md` (Sprint 1: tickets S1-01…S1-17, gate checklist), `docs/astrid-first-sprint-plan-review-20260813.md` (fixes 2/3/10 apply here). Plugin/generalization feedback source: `docs/openrouter-chat-20260814-plugin-data.md`. Vision context (kernel/pack layering, kernel audit, promotion rule): `docs/unified-data-master-plan-20260814.md`.

## Outcome

The transactional foundation of the new Astrid: the exact 20-table SQLite Astrid schema factored as an agent-agnostic 14-table kernel plus in-tree timeline, shots, and references packs; pack-aware checksummed migrations; explicit startup `register_pack()` registration; and the single-writer repository layer with the atomic unit-of-work (append events + advance stream/project head + update projection + write receipt + bump change cursor in ONE `BEGIN IMMEDIATE`). Project and timeline repositories include whole-document CAS save, and a THIN frozen bridge exposes `/health`, `/projects`, timeline list/load/save over the existing wire contract — proven by the current editor's real provider test doing list/load/save/reload, stale save → 409, restart retains the save. A reviewer can run one command and see: a fresh Astrid DB with all 20 tables expressed as core plus installed-pack catalogs, receipt/replay/crash/contention suites green, bridge up, editor save test green.

## Scope

IN (maps to sprint-plan S1-01…S1-17):
- Creation migrations for the exact 20-table Astrid catalog + indexes and PRAGMAs: `schema_migrations.pack TEXT NOT NULL DEFAULT 'core'`, composite `PRIMARY KEY (pack, version)`, independently checksummed forward-only core/pack migrations in dependency order, and too-new core or pack schema fails read-only/clearly.
- A pack-aware catalog manifest/fixture that compares core tables plus the tables declared by installed packs; it still totals 20 for Astrid, while a kernel-only or differently packed agent is not forced to claim 20.
- Repository write queue / UoW; canonical request hashing; command receipts with idempotent replay and mismatched-key rejection; registry-backed stream factories and namespaced event/command vocabulary. Remove the closed `event_streams.stream_type` DDL `CHECK`; validate `core.project`, `core.task`, `core.run`, and pack-declared types (including `timeline.timeline`) in repositories.
- Establish `core/` + in-tree `packs/{timeline,shots,references}`. Each pack has a manifest (`id`, `version`, `depends_on`, migrations, stream/event/command kinds, repositories, conformance, CLI/bridge mounts) and joins the registries via one explicit `register_pack()` call at startup; no dynamic loader.
- Package the receipt/replay/mismatch, same-project, and statement-boundary crash harnesses as a reusable kernel conformance kit for every pack command. Extend import/schema lint to reject kernel-to-pack FKs/imports and pack-owned/direct writers.
- `ProjectRepository` and `TimelineRepository` (create/list/show; timeline whole-document CAS save: document + registry + event + head + receipt atomic, stale → no mutation).
- Statement-boundary crash harness and writer-contention test.
- Thin frozen bridge routes over the existing wire contract (no fallback to file/JSONL/FSA/Supabase); early real `AstridBridgeDataProvider` test.
- Decision artifact (`docs/astrid-v10-implementation-decisions.md`): managed media root/staging/reference-in-place, fan-out max + continuation envelope, media relation kinds (before m2), evidence + reference vocabularies (before m3), platform-matrix owner/deadline (before m6) — S1-16a–d.

OUT: executor, media pipeline, references/shots implementations, CLI families beyond the thin bridge, backup/doctor, packaging, any legacy import, any plan/step machinery.

## Locked decisions

- v10 is normative: 20 tables, task/event principle, atomic receipts, single writer, byte-hash media identity (schema only here), timeline CAS, no plans/steps, no FSA, no Supabase, no legacy import.
- Plugin laws are normative: packs FK into kernel only; kernel never FKs into packs and uses polymorphic event subjects; cross-pack links use only `media_id`/`task_id`; packs receive the kernel UoW and never own writers; pack vocabulary is namespaced and registry-validated; every pack command uses the kernel conformance kit.
- Boundary now, loader later: only the three in-tree Astrid packs are explicitly registered at GA. No dynamic discovery, install/uninstall, or third-party loader ships.
- Wire contract frozen: timeline GET (config+registry combined), save POST with integer `expected_version`, typed 409 `timeline_version_conflict` with current `config_version`, typed 422, 404 forms; internal receipts never leak into responses; `config_version` IS the timeline stream head.
- One writer queue, `BEGIN IMMEDIATE`, WAL + documented durability mode; canonical UTC/JSON/hash library; lowercase ULIDs for fresh objects (imported timeline UUID/ULID aliases NOT in scope this milestone — no legacy).
- Editor test lane: the current editor's provider/persistence tests are the acceptance gate (no continuity ceremony).

## Constraints

- GA invariants from v10 §5.1 hold from the first commit: atomic receipts, idempotency, terminal immutability (schema-level hooks only here), timeline CAS, single writer.
- Zero secrets in events/receipts/logs; nothing requires accounts/cloud/provider credentials.
- No table beyond the 20-table installed Astrid catalog; the kernel remains exactly 14 tables and no plan/step/legacy/dormant-platform columns appear.
- Import lint enforces pack FK direction and prevents pack-owned/direct writers in addition to the existing authority rules.
- Existing editor must keep working against the thin bridge (its provider tests are the gate).

## Done Criteria

Sprint-1 gate (sprint-plan §6 checklist) all "yes", plus: one command creates a fresh DB, verifies the 14 core tables plus all installed-pack tables (20 total for Astrid), runs receipt/replay/crash/contention suites, starts the bridge, runs the focused editor save test, and retains output in CI. The migration runner records and validates `(pack, version)`, applies dependency-ordered migrations independently, rejects changed checksums and too-new core/pack schemas, and the registry rejects undeclared stream/event/command kinds. Each in-tree pack has a manifest and registers through the single startup path; the reusable pack conformance kit and FK-direction/no-direct-writer lint are green. Crash injection at every statement boundary of project-create and timeline-save yields old-or-complete. Decision artifact exists with named values/owners for all five items.
